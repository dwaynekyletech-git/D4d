# Data Model: Documentation for Dummies Agent

**Date**: 2025-10-03
**Phase**: 1 - Design & Contracts
**Related**: [plan.md](./plan.md), [research.md](./research.md)

## Overview

This document defines the data entities and their relationships for the Documentation for Dummies agent. All entities use TypeScript types aligned with AI SDK 5 patterns and Next.js 15 conventions.

## Entity Definitions

### 1. Message

**Purpose**: Represents a single message in the conversation between user and agent.

**TypeScript Type** (from AI SDK):
```typescript
interface UIMessage {
  id: string;
  role: 'user' | 'assistant' | 'system';
  parts: MessagePart[];
  createdAt?: Date;
}

type MessagePart =
  | TextPart
  | ToolCallPart
  | ToolResultPart
  | SourceUrlPart;
```

**Fields**:
- `id`: Unique identifier (generated by AI SDK)
- `role`: Message source - 'user', 'assistant', or 'system'
- `parts[]`: Array of message components (text, tool calls, tool results)
- `createdAt`: Optional timestamp (auto-generated)

**Lifecycle**:
1. **Created**: When user submits question or agent starts response
2. **Streaming**: Agent message parts stream in progressively
3. **Complete**: All parts received, message finalized
4. **Destroyed**: On browser tab close (session-only)

**Storage**: Browser memory via useChat React state (no persistence)

**Validation Rules**:
- `id` must be unique within conversation
- User messages must have at least one TextPart
- Assistant messages may have multiple parts (text + tool calls)
- `role` cannot change after creation

**Related Entities**: Part of Session, contains MessageParts

---

### 2. ToolCall

**Purpose**: Represents a call to the retrieve-documentation tool during agent response.

**TypeScript Type** (from AI SDK):
```typescript
interface ToolCallPart {
  type: 'tool';
  toolName: string;
  toolCallId: string;
  input: Record<string, unknown>;
  result?: unknown;
}
```

**Fields**:
- `type`: Always 'tool'
- `toolName`: 'retrieve-documentation'
- `toolCallId`: Unique identifier for this tool invocation
- `input`: `{ query: string }` - search query for documentation
- `result`: Documentation retrieval response (optional during execution)

**Tool Input Schema** (Zod):
```typescript
z.object({
  query: z.string().describe('Search query for technical documentation')
})
```

**Tool Result Schema**:
```typescript
{
  documentation: string | null;
  available: boolean;
  message?: string; // Error/unavailable message
}
```

**Lifecycle**:
1. **Initiated**: Model decides to call tool, creates ToolCallPart with input
2. **Executing**: Tool's execute function runs, retrieves from Context7 MCP
3. **Completed**: Result added to ToolCallPart
4. **Failed**: Result contains `available: false` with error message

**Integration**: Context7 MCP server via HTTP transport

**Error States**:
- Documentation not found: `available: false`, `documentation: null`
- MCP server unavailable: `available: false`, `message: "service unavailable"`
- Network timeout: `available: false`, `message: "request timeout"`

**Related Entities**: Part of Message, depends on Context7MCPConnection

---

### 3. Session

**Purpose**: Represents the complete conversation session between user and agent.

**TypeScript Type**:
```typescript
interface ConversationSession {
  messages: UIMessage[];
  status: 'idle' | 'loading' | 'error';
  startedAt: Date;
}
```

**Fields**:
- `messages[]`: Array of all messages in conversation (chronological)
- `status`: Current conversation state from useChat
- `startedAt`: Session creation timestamp

**Lifecycle**:
1. **Created**: On page load, when component mounts
2. **Active**: User asking questions, agent responding
3. **Destroyed**: On browser tab/window close, page refresh

**Storage**: Browser memory only (React state)
  - Managed by `useChat` hook
  - No localStorage, sessionStorage, or database
  - Cleared on unmount/reload per FR-011

**Constraints**:
- Maximum messages: ~100 (practical UI limit, no hard enforcement)
- Session duration: Unlimited (while tab open)
- History: Not preserved across sessions

**State Transitions**:
```
Created (idle) → Active (loading) → Waiting (idle)
             ↓                    ↓
          Error → Can retry → Active
```

**Related Entities**: Contains Messages, which contain ToolCalls

---

### 4. DocumentationSource

**Purpose**: Represents a documentation resource retrieved from Context7 MCP.

**TypeScript Type**:
```typescript
interface DocumentationSource {
  query: string;
  content: string | null;
  available: boolean;
  retrievedAt: Date;
  errorMessage?: string;
}
```

**Fields**:
- `query`: Original search query sent to Context7
- `content`: Retrieved documentation text (null if unavailable)
- `available`: Boolean indicating successful retrieval
- `retrievedAt`: Timestamp of retrieval attempt
- `errorMessage`: Optional error description (when available=false)

**Lifecycle**:
1. **Requested**: Tool execute function invoked with query
2. **Retrieving**: HTTP request to Context7 MCP server
3. **Retrieved**: Content returned (may be empty)
4. **Failed**: Error occurred, available=false

**Storage**: Transient (exists only during tool execution, result stored in ToolCallPart)

**Integration Points**:
- Context7 MCP server (external dependency)
- MCP client (`/lib/mcp-client.ts`)
- retrieve-documentation tool (`/components/agent/tools/retrieve-documentation.ts`)

**Related Entities**: Returned as ToolCall result

## Entity Relationships

```
Session
  ├─> messages: UIMessage[]
      ├─> parts: MessagePart[]
          ├─> TextPart (user question or agent explanation)
          ├─> ToolCallPart (documentation retrieval)
          │   ├─> input: { query: string }
          │   └─> result: DocumentationSource
          └─> ToolResultPart (retrieval result display)
```

**Cardinality**:
- 1 Session : N Messages (1:many)
- 1 Message : N Parts (1:many)
- 1 ToolCallPart : 1 DocumentationSource (1:1)

---

## State Management

**Primary State Manager**: `useChat` hook from `@ai-sdk/react`

**State Location**: Browser memory (React component state)

**Persistence Strategy**: None (session-only per constitution and FR-011)

**State Shape**:
```typescript
const {
  messages,    // UIMessage[]
  status,      // 'idle' | 'loading' | 'error'
  input,       // string (current user input)
  sendMessage, // (message: { text: string }) => void
  reload,      // () => void
  stop,        // () => void
} = useChat({
  api: '/api/doc-for-dummies-agent',
});
```

---

## Data Flow

1. **User Input**:
   - User types question in PromptInput component
   - Calls `sendMessage({ text: question })`
   - useChat adds user message to messages array

2. **Agent Processing**:
   - API route receives messages
   - Converts to ModelMessages via `convertToModelMessages()`
   - Calls `streamText()` with tools enabled
   - Model decides whether to call retrieve-documentation tool

3. **Tool Execution** (if needed):
   - Tool's execute function calls MCP client
   - MCP client queries Context7 server via HTTP
   - Documentation returned or error handled
   - Result added to tool call part

4. **Response Streaming**:
   - Assistant message streams back via `toUIMessageStreamResponse()`
   - useChat updates messages array with streaming parts
   - UI rerenders progressively

5. **Session End**:
   - User closes tab/window
   - React unmounts component
   - useChat state destroyed
   - No persistence, fresh session on reload

---

## Validation Rules Summary

**Message Validation**:
- User messages: Must have text content
- Assistant messages: May have text + tool calls
- IDs must be unique within session

**ToolCall Validation**:
- Input must match Zod schema: `{ query: string }`
- Result must indicate availability: `{ available: boolean }`
- toolName must be 'retrieve-documentation'

**Session Validation**:
- Messages must be chronologically ordered
- No message modification after creation (immutable)
- Status transitions must follow state machine

**Type Safety**:
- All entities defined as TypeScript types/interfaces
- Zod schemas for tool inputs
- AI SDK types for message structures
- Strict mode enabled (`pnpm tsc --noEmit` must pass)
